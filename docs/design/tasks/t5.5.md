=== THE BUG ===
Installed @tanstack/react-query is 5.102.8. In this version a mutation's onSuccess / onError /
onSettled receive FOUR arguments:
    onSuccess(data, variables, onMutateResult, context)
    onError(error, variables, onMutateResult, context)
    onSettled(data, error, variables, onMutateResult, context)
(`onMutateResult` is what onMutate returned; `context` is the MutationFunctionContext.)
Verify against node_modules/@tanstack/query-core type definitions (search for `onSuccess?:` in the
mutation options type) before editing.

src/api/hooks/adminHooks.ts around line 241 (the update-object mutation):
    onSuccess: (data, variables, context) => {
      queryClient.invalidateQueries(...);
      (onSuccess as any)?.(data, variables, context);
    },
It names the 3rd parameter `context` but it is actually `onMutateResult`, and it drops the real 4th
argument, so a caller's onSuccess receives the wrong value in position 3 and `undefined` in position 4.
`withInvalidation` (around line 123) already forwards all four correctly — use it as the reference.
