=== THE BUG ===
In the `groupByModel` useMemo there is a `derivedGroup` IIFE that assigns every model
a group by splitting its name. Its last fallback rule splits on a SINGLE underscore:

    if (model.name.includes("_")) { return model.name.split("_")[0]; }
    return "Other";

So `order_item`, `order_line`, `order_refund` become group "Order"; `product_image`
becomes "Product"; and every single-word model (`user`, `product`, `invoice`) falls
into one enormous group literally labelled "Other". The result is a sidebar with
roughly 25 one-item groups and an "OTHER" mega-bucket. It is unusable.

=== THE FIX ===
Replace the grouping rules with this precedence, exactly:

1. If `configData.model_groups` (or the camelCase / by_app variants already handled
   in the existing code) supplies a label for the model, USE IT. Keep the existing
   config-parsing code that builds `modelGroupMap` — do not change it.

2. Otherwise, derive a group ONLY from a genuine namespace separator:
     - if the name contains "."  -> the part before the first "."
     - else if it contains "__"  -> the part before the first "__"
     - otherwise -> NO GROUP (see rule 3). Do NOT split on a single "_".
   Deleting the single-underscore rule is the core of this fix.

3. Models with no group go into a single UNGROUPED bucket. Represent it with the
   sentinel label `""` (empty string). It must NOT be labelled "Other".

=== RENDERING RULES ===
Change the returned shape of `groupByModel` so each entry carries its label and
whether it is the ungrouped bucket. Suggested shape:

    { label: string; models: any[] }[]     // label === "" means ungrouped

Ordering: the ungrouped bucket renders FIRST, then the named groups sorted
alphabetically. (Today everything is sorted alphabetically; the ungrouped bucket
must jump the queue.)

In the JSX that maps over `groupByModel`:
  - When `group.label === ""`, render the model buttons with NO <h5> heading at all.
  - Additionally: if `groupByModel.length <= 1`, render NO headings at all, even for
    a named group — a single group needs no header.
  - Otherwise render the existing <h5> heading exactly as it is today.

Keep the existing per-model sort (`verbose_name_plural.localeCompare`) unchanged.
