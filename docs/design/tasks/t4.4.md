=== THE DEFECT ===
On a narrow screen the data table overflows horizontally inside its scroll container.
There is no visual cue that more columns exist, and the identity column (the first
data column, which is how a user knows WHICH row they are looking at) scrolls out of
view, so the remaining columns become meaningless.

=== FIX 1: a scroll-shadow affordance ===
Find the element that wraps the <Table> and provides horizontal scrolling (it will
have `overflow-x-auto` or similar). Add a CSS-only scroll shadow using background
gradients — no JS scroll listeners, because they cause churn on every scroll frame.

Add this class string to that wrapper, alongside its existing classes:

    "[background:linear-gradient(to_right,hsl(var(--surface-2))_30%,transparent),linear-gradient(to_right,transparent,hsl(var(--surface-2))_70%)_right,radial-gradient(farthest-side_at_0_50%,rgba(0,0,0,0.12),transparent),radial-gradient(farthest-side_at_100%_50%,rgba(0,0,0,0.12),transparent)_right] [background-repeat:no-repeat] [background-size:40px_100%,40px_100%,14px_100%,14px_100%] [background-attachment:local,local,scroll,scroll]"

This is the standard pure-CSS scroll-shadow technique: the two `local` gradients are
painted with the content and mask the shadows when scrolled to either end, while the
two `scroll` radial gradients are pinned to the container edges.

=== FIX 2: sticky identity column ===
In the table body cell renderer, the first data column is identified by
`const isPrimary = colIdx === 0;`. There is also a leading checkbox <TableCell> before
the mapped columns, and a matching header cell.

Make BOTH the checkbox column and the first data column sticky to the left:

- On the checkbox <TableCell> and its corresponding <TableHead>, add:
      "sticky left-0 z-20 bg-surface-2"
  (on the header cell use `bg-surface-sunken` instead, so it matches the header fill)

- On the first data column — i.e. when `isPrimary` is true — add to that <TableCell>:
      "sticky left-[var(--sticky-id-offset)] z-20 bg-surface-2"
  and to the matching <TableHead> for column index 0:
      "sticky left-[var(--sticky-id-offset)] z-20 bg-surface-sunken"

- Define the offset once on the table wrapper element as an inline style:
      style={{ ["--sticky-id-offset" as any]: "3rem" }}
  3rem is the width of the checkbox column.

- On a selected row the sticky cells must not show the row highlight through the
  sticky background. Where the row already applies a selected background, make the
  sticky cells inherit it by using `bg-inherit` instead of `bg-surface-2` on those
  two cells, and ensure the <TableRow> itself carries the background class.
  Prefer `bg-inherit` on the sticky cells — it is simpler and always correct.

- Only apply the sticky behaviour from the `sm` breakpoint DOWN is NOT required —
  sticky columns are useful at every width. Apply them unconditionally.
