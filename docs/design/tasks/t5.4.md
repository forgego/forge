=== THE BUG ===
The Go admin API returns validation failures as HTTP 400 with this body
(forge/admin/api/rest/router.go respondError + validationDetails):

    {
      "error": {
        "code": "validation_error",
        "message": "validation failed: ...",
        "details": { "email": ["Enter a valid email"], "non_field_errors": ["..."] }
      }
    }

But src/pages/ModelUpsertPage.tsx (catch block of handleSubmit, around line 253) reads the TOP level:

    const errorData = error.response?.data;
    const errorMsg = errorData?.message || "Failed to save changes. Please try again.";
    if (errorData?.details) { setFieldErrors(errorData.details); }

`data.message` and `data.details` never exist, so per-field errors are NEVER shown and the toast
always says the generic message. (LoginPage.tsx and api/client.ts already read data.error.message
correctly — follow that.)

1. Create src/api/errors.ts:

     export interface ApiErrorInfo {
       code?: string;
       message: string;
       fieldErrors: Record<string, string[]>;   // excludes non_field_errors
       formErrors: string[];                    // from details.non_field_errors
     }

     export function parseApiError(error: unknown, fallback: string): ApiErrorInfo

   Rules:
   - body = (error as any)?.response?.data
   - message: body?.error?.message, else body?.message (legacy), else (error as Error)?.message
     ONLY IF it is not an axios generic "Request failed with status code NNN", else fallback.
   - details = body?.error?.details ?? body?.details (legacy). If it is an object, for each key:
       value is string[] -> keep strings; value is string -> [value]; anything else -> skip.
     Key "non_field_errors" goes to formErrors; every other key to fieldErrors.
   - Never throw; non-object inputs return { message: fallback, fieldErrors: {}, formErrors: [] }.
   - No `any` in exported types.
