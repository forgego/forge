=== THE BUG (defect VB-11) ===
`SidebarItem` is currently declared as a `const` arrow component INSIDE the body of
the `AdminLayout` function component. That means React sees a brand-new component
TYPE on every single AdminLayout render. React therefore unmounts and remounts the
entire nav subtree on every render, which destroys each item's local `expanded`
useState. Expanded plugin menus collapse on their own. This is a real bug, not styling.

The fix is to move `SidebarItem` to MODULE SCOPE (top level of the file, outside and
above `export default function AdminLayout`), and pass everything it currently closes
over in as props.

=== WHAT IT CLOSES OVER TODAY ===
Read the current code carefully. `SidebarItem` uses these from the enclosing scope:
  - `location` (from useLocation) — used indirectly via isMenuEntryActive / isEntryMatch
  - `isMenuEntryActive(entry)` — helper defined in AdminLayout
  - `isEntryMatch(item)` — helper defined in AdminLayout
  - `normalizeAdminPath(item.path)` — ALREADY at module scope, needs no prop
  - `go(path)` — navigation helper defined in AdminLayout
